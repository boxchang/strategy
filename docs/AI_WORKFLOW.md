# AI Agent 工作流程與提示詞

## 1. 任務分類

AI 先判斷任務類型：
- 新策略設計
- 既有策略除錯
- 策略邏輯修改
- 回測分析
- 參數優化
- 程式重構
- 部署 / 設定檢查

不可把「修改程式」和「策略優化」混為一談；若使用者只要求修 bug，不應順便改交易邏輯。

## 2. 標準流程

### A. 需求理解
- 重述策略假設與目標。
- 列出已知條件、未知條件與衝突。
- 需要關鍵資訊時，只詢問必要問題。
- 未知資訊不可自行補成事實。

### B. 專案檢查
- 檢查目標檔案與相關設定。
- 確認 Freqtrade / Python 版本。
- 檢查 Git working tree。
- 確認不會碰觸其他 Bot、資料庫或 secrets。

### C. 設計
- 先寫出條件表或偽程式碼。
- 說明 Long / Short、進出場、停損與倉位。
- 列出風險與測試案例。

### D. 實作
- 採最小修改。
- 不刪除使用者未要求刪除的功能。
- 以清楚 diff 說明變更。

### E. 驗證
- 執行語法、載入、lookahead 與回測檢查（依任務適用）。
- 只報告實際執行結果。
- 無法執行時，提供命令並標示待使用者執行。

### F. 交付
- 檔案清單
- 變更摘要
- 測試結果
- 回測結果（若有）
- 未解決風險
- 下一步建議

## 3. 通用任務提示詞

請先閱讀 `CLAUDE.md` / `AGENTS.md` 及其引用的所有相關規範，再處理我的任務。

任務：<在此描述>

限制：
- 不要修改未指定的策略或設定。
- 不要自行改變交易邏輯以外的功能。
- 不得虛構測試或回測結果。
- 先列出計畫與風險，再執行必要修改。
- 完成後提供檔案差異、測試命令、實際結果與未驗證事項。

## 4. 回測分析專用提示詞

請讀取 `docs/BACKTEST_AND_SCORING.md`，分析我提供的回測結果。

要求：
1. 先檢查回測設定與資料期間是否可比較。
2. 分析淨利、最大回撤、Profit Factor、交易數、勝率、平均盈虧、持倉時間。
3. Long / Short、交易對、月份或年度分開分析。
4. 檢查成本、funding、滑價與 OOS 穩健性。
5. 指出策略失效的市場環境。
6. 不要只追求最高報酬；優先考慮風險調整後的穩健性。
7. 提出可驗證的下一輪實驗，一次盡量只改一個核心假設。
8. 不可把回測結果描述成未來收益保證。

## 5. 策略修改專用提示詞

請先讀取所有策略與風控規範，檢查目前策略的完整程式及相關設定。

修改目標：<描述>

在修改前：
- 解釋目前邏輯。
- 找出與需求相關的程式位置。
- 列出可能影響的其他功能。

修改後：
- 提供完整修改摘要。
- 比較修改前後的訊號差異。
- 執行可行的程式檢查。
- 提供回測命令，但不可宣稱未執行的結果。
