# 風控規範

> 本文件是工程風險控制基線，不構成投資建議。實際參數需由使用者核准，AI 不得自行提高風險。

## 1. 預設安全政策

- 新策略與新 Bot 預設 `dry_run = true`。
- Live trading 必須取得使用者明確授權。
- 預設不使用 DCA、無限加倉、馬丁格爾或追繳式補倉。
- 預設採 isolated margin；實際交易所支援性需核對。
- 槓桿預設以 1x 作為測試起點；任何提高槓桿需說明風險並由使用者決定。
- 設定每筆 stake、最大持倉數、最大總曝險與每日/每週停手機制。
- API key 不得具備提領權限；使用 IP 白名單（若可用）。

## 2. 必須計算的風險

AI 必須檢查並報告：
- 單筆交易風險（含槓桿、停損距離、費用與滑價）
- 同時持倉的總風險
- 同方向或高相關交易對的集中度
- 最大回撤及回撤持續時間
- 連續虧損情境
- 資金費率對持倉的影響
- 流動性不足、跳空、滑價與停損未成交風險
- 交易所維護、API 失聯、Bot 停止及資料延遲風險

## 3. 停損與退出

- 每個策略必須有明確停損。
- 說明 Freqtrade stoploss 是以交易報酬、價格變動或槓桿後報酬的哪種語義，依安裝版本確認。
- 若使用 stoploss on exchange，確認交易所、合約類型、訂單類型與 Freqtrade 版本支援。
- 不能假設停損委託一定能成交或能避免清算。
- 必須檢查 ROI、exit signal、trailing stop、custom stoploss 之間的交互作用。

## 4. 共用交易所帳戶

若人工交易與 Bot 共用帳戶：
- Bot 不得假設帳戶中的所有倉位都是自己建立的。
- 手動倉位不會自然成為 Bot 的 Trade 記錄，也不應假設 Bot 會管理其停損或退出。
- 同幣種手動倉位可能與 Bot 倉位合併、互相影響或造成交易記錄不同步，具體行為依交易所 position mode 與 Freqtrade 實作確認。
- 手動交易可能占用共享可用保證金。
- 建議使用獨立子帳戶；若無法使用，建立啟動前檢查、同幣種隔離與人工接管 SOP。
- 重新啟動前核對交易所倉位、未成交訂單、保護性訂單及 Freqtrade DB 未平倉 Trade。
- 不可只憑 Telegram `/pause` 或 `/stop` 就認定已完成安全交接；需確認 bot 對倉位與交易所訂單的實際管理狀態。

## 5. 風險變更審批

以下變更需明確告知使用者並取得確認：
- 提高槓桿或 stake
- 增加最大持倉
- 啟用 DCA / position adjustment
- 放寬 stoploss
- 移除停損或保護機制
- 改變 margin mode / position mode
- 切換 Dry Run 至 Live
- 更換 API key 或交易所帳戶

## 6. 緊急停止計畫

每個實盤 Bot 必須有書面 SOP，至少包括：
1. 暫停新進場。
2. 確認 Bot 是否仍管理現有 Trade。
3. 檢查交易所實際倉位與未成交訂單。
4. 決定由 Bot 或人工單一管理者接管；避免雙方同時操作同一倉位。
5. 核對停損單、止盈單及取消訂單行為。
6. 恢復前完成 DB 與交易所狀態對帳。

任何停機指令的副作用都必須依目前 Freqtrade 版本和設定先驗證，不可想當然耳。
