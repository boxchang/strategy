# 策略開發規範

## 1. 策略開發原則

每個策略必須先提出可被驗證的交易假設，而不是先堆疊指標或追求漂亮回測。策略規格應說明：
- 市場行為假設與適用市場狀態
- 交易方向：Long、Short 或雙向
- 交易週期、訊號週期及 informative timeframe
- 進場、出場、停損、停利及逾時退出
- 倉位大小、槓桿、最大持倉與是否允許加倉
- 不適用的市場條件
- 預期交易頻率及持倉時間

## 2. 進場與出場

- Long 與 Short 條件須分開描述、分開檢查。
- 每個條件須能對應到程式欄位或可測試的布林條件。
- 說明訊號使用當根已收盤 K 線還是盤中資料。
- 預設只使用已完成 K 線；如使用盤中訊號，必須明確說明重繪、觸發與回測差異。
- 避免同一根 K 線同時產生互相矛盾的進場訊號；定義優先順序或排除條件。
- 必須定義 exit signal、stoploss、ROI / trailing stop 的優先關係。
- 不可只依賴反向進場訊號作為出場機制。
- 若使用 custom_exit / custom_stoploss / order_filled 等 callback，先核對安裝版本的 API、呼叫時機與參數。

## 3. 指標與資料

- 每個指標都要說明交易假設、計算週期與使用欄位。
- 設定足夠的 `startup_candle_count`，並驗證資料量足夠。
- informative timeframe 必須使用 Freqtrade 正確的資料合併方法，避免未來資料洩漏。
- 不可用未來 K 線、未來最高/最低價或尚未發生的成交資訊決策。
- 不可在回測中使用實盤才可取得、但歷史上無法重建的資料，除非明確標示限制。
- 不可在 `populate_*` 中依賴逐筆即時狀態或外部未固定資料。

## 4. 倉位與加倉

- 預設不啟用 DCA / position adjustment。
- 若使用加倉，必須定義最大加倉次數、每次 stake、總曝險上限、最壞情境及退出規則。
- stake sizing 必須與可用資金、最大持倉及交易所限制一致。
- 不可假設槓桿會降低風險；槓桿會放大盈虧與清算風險。
- 必須考慮最小下單量、精度、最小名目價值及資金費率。

## 5. 策略類別與模組化

建議策略以單一明確核心假設為主。若混合趨勢與均值回歸，需定義 regime classifier、切換條件、兩套訊號優先順序及衝突處理。避免為了提升回測而不斷追加條件。

## 6. 策略交付最低要求

- 策略類別名稱與版本
- 使用的 timeframe / informative timeframe
- Long / Short 進場與出場表
- stoploss、ROI、trailing stop、leverage、stake 規則
- 交易成本假設
- 可能失效的市場狀態
- 語法與策略載入檢查結果
- 回測結果或明確聲明尚未回測
